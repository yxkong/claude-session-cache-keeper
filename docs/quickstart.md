# CacheKeeper · by yxkong

一个应用包同时包含桌面管理界面和 Claude Code 连接插件，不需要分别下载。应用不保存 API Key，请求复用原 Code 会话的 API 配置。

## 开始使用

1. macOS：打开 DMG，把 CacheKeeper 拖入 Applications。Windows：解压 ZIP，运行 CacheKeeper.exe。Linux：解压 tar.gz，以普通用户运行目录中的 CacheKeeper 可执行文件。
2. 先安装并登录 Claude Code CLI；打开 CacheKeeper，点击「安装连接插件」。插件会被复制到固定的用户数据目录，应用更新位置不会改变插件来源。
3. 已有 Code 会话重载插件，确认应用显示执行器 0.2.x。若仍显示旧版，待任务完成后重启 Claude；重启会中断正在运行的任务。
4. 选中需要保活的会话，设置随机间隔、次数和缓存规模门槛，点击「应用设置并开启」。每条新连接默认关闭，其他会话不受影响。

默认随机间隔 260～280 秒，连续空闲最多尝试 6 次。首次连接还没有观察到有效缓存时，等待下一次正常工作请求完成，不会立即付费探测旧缓存。

正常工作请求重置尝试预算；保活不重置。达到次数上限、失败、未命中、错过缓存窗口时停止本轮。输入参数错误时仍可停止已开启的会话。API 费用由原会话承担，实际缓存行为取决于你的 API 供应源。

关闭窗口后应用留在托盘；正常退出会停止已知连接的后续保活。强制结束进程时仍可能执行本轮剩余尝试。已经发出的请求无法撤回。

## 从旧 Mac 版迁移

先退出旧版管理应用。新版可以显示旧连接，但只能停止，不能再次开启。安装连接插件时会停止旧连接并停用旧插件，避免两个执行器重复保活。安装失败会尝试恢复旧插件的启用状态，保活开关保持停止，由你决定是否重开；若无法安全恢复，会保留停止状态并显示错误。

数据目录为用户主目录下的 `.cache-keeper`，不含 API Key。应用按已连接的会话 ID 读取本地转录尾部的标题元数据，不把完整对话写入桥接文件。

## 平台与验证边界

需要支持 hooks modules 的 Claude Code CLI，以及支持缓存的模型/API。普通 Claude Chat 不属于本工具的连接对象。

本地跨平台运行包不等于目标系统已验证。Windows 和 Linux 的实际启动/运行验证，以及 CI 原生安装器，见同目录发布验证记录。Linux 需要满足 Electron 的系统库和沙箱要求，本项目不附带关闭沙箱的启动参数。

当前本地构建没有 Mac Developer ID 公证或 Windows 发布签名，操作系统可能提示无法验证发布者。正式公开分发需要发布者自行完成签名与公证。

## 更新

0.3.0 起，从右上角或托盘的“检查更新”分别下载应用、连接插件。插件可独立更新；等待任务结束、停止保活后安装，再在目标会话手动重载。旧版 0.2.0 需先手动安装新版应用。当前本地包通过下载后手动替换升级；正式原生包按签名能力提供安装入口。远程仓库需先发布完整 Release。详见 `updates.md`。
