# CacheKeeper 0.4.0

## 范围与验收

独立桌面应用包含连接插件。用户下载对应系统的应用包，在应用中安装连接插件后，选择会话并单独开启保活。支持 macOS、Windows、Linux 的同一界面与本地文件协议；API 请求继续由 Claude Code 原会话发送，应用不持有 API Key。

保留默认随机 260～280 秒、默认建议连续空闲尝试 6 次、可选最小缓存 token 门槛。间隔允许 30～280 秒的整数，最短不超过最长；尝试次数允许正安全整数，不设业务上限；token 门槛为 0～1000 万的整数。达到用户配置的次数后结束本轮。每条新连接默认关闭；保存配置不自动开启；正常请求重置预算，保活不重置。缓存未命中、失败、过期或次数耗尽时停止本轮。不能保证自定义 API 源的缓存命中或固定金额费用。

## 迁移设计

0.4.0 用 Tauri 2、Rust 和系统 WebView 替换 Electron。保留现有 HTML/CSS/JavaScript 界面，不引入新前端框架；会话读写、标题解析、CLI 安装、GitHub 下载与更新均由 Rust 负责。分发包不包含 Chromium、Node、Bun、node_modules 或测试辅助程序。

以 [CC Switch 4.0.23](https://github.com/farion1231/cc-switch/tree/v4.0.23/src-tauri) 的架构和发布流程为参考。它的 Mac 通用 DMG 为约 36 MiB。原 Electron 版本 Mac 通用包约 217 MiB、安装后约 500 MiB；体积是本次替换的直接原因。安装包预算为 Mac 40 MiB、Windows 30 MiB、Linux DEB 30 MiB、Linux AppImage 120 MiB；AppImage 会携带更多系统依赖，单独衡量。

`plugin/hooks/policy.ts` 仍是保活参数和状态机的唯一 owner。构建器导出限制、默认值和边界样例；Rust 编译嵌入生成结果并用同一批样例核验。连接插件 0.2.2 增加参数元数据导出，执行行为和桥接协议 1 保持兼容。

## 状态与安全边界

列表状态点只表示连接与工作状态：蓝色工作中、绿色在线、灰色离线，与底部图例一致。保活开关、同步和续热结果在提示与详情中显示；详情说明必须对应当前暂停原因，正在正常工作时优先显示工作状态。

支持 Claude Code CLI 与 Claude Desktop 的本地 Code 会话。应用一键安装优先查找 CLI，也可发现 Desktop 的本地版本化 Code 执行器缓存；未发现时可先启动 Desktop 本地 Code 会话或通过其插件管理器安装。

首次打开显示三步引导：安装连接插件 → 在目标会话重载并等待连接上报 → 选择会话、设置并明确开启。允许跳过和按 Escape 退出，完成或跳过后将引导版本写入本机数据目录的 `ui-preferences.json`；再次启动不重复提示，底栏与系统/托盘菜单可重新打开。保存偏好失败时仍允许使用，并说明下次会再提示。引导本身不安装插件、不修改会话开关；安装和开启均由明确点击触发。

底栏保留简短产品说明，提供使用帮助、GitHub、公众号与重载命令入口；左侧版本按钮打开“关于”。“关于”集中展示说明、版本、作者、项目与 Issues 链接、公众号「5ycode」及复制名称，系统菜单使用同一内容。产品资料来自 `app/core/product.json`，仓库地址复用 `release-config.json`。外链由 Rust 按固定标识生成，前端不能传任意 URL；演示偏好随隔离数据目录保存。

设计借鉴 [CC Switch v4.0.23 的首次提示](https://github.com/farion1231/cc-switch/blob/v4.0.23/src/components/FirstRunNoticeDialog.tsx)的本机确认状态与[关于页](https://github.com/farion1231/cc-switch/blob/v4.0.23/src/components/settings/AboutSection.tsx)的信息组织。沿用现有 WebView 与对话框，不引入其 React/UI 依赖，也不添加强制关注或 Star 弹窗。验收覆盖首次显示、完成与跳过持久化、重新查看、链接和复制反馈、原生菜单路由及不产生会话控制文件。

执行器使用各系统用户主目录下的 `.cache-keeper/`，可由 `CACHE_KEEPER_DATA_DIR` 覆盖。macOS 可显示旧版 `ClaudeCacheKeeper` 数据，但旧连接只允许停止。安装新版插件前停用旧插件与旧开关，避免两份执行器同时花费。失败恢复原 marketplace；只有确认新版已停用才恢复旧插件，保活开关保持停止。

应用只显示已发布连接，按本机转录元数据显示真实标题，不通过模型猜标题。未完成的状态写入保留最近一份有效快照。控制请求只接受会话 ID 和参数，由 Rust 核对快照、在线状态、执行器能力及参数后原子写入。前端不接受任意文件路径，没有通用文件、shell、网络或更新器权限。

关闭窗口后留在托盘；正常退出先停止已知连接，停止失败时保留应用并显示原因。强制退出仍可能保留已开启轮次的剩余尝试。插件更新不自动重载或重启 Claude；以目标会话报告的版本确认加载。正在工作、续热或保活开启时不能安装插件或原生应用更新。

## 实现与验收顺序

1. Rust 会话桥接：合成会话读取、单条保存、默认关闭、停止、旧连接、真实标题及边界校验。
2. 保留界面：通过原生 Rust 测试进程运行组件测试，核验草稿、停止按钮、状态点及更新入口。
3. 安装和更新：CLI 参数边界、超时、禁止降级、失败恢复、来源白名单、体积与 SHA-256、签名、取消下载。
4. 原生交付：本机 Mac 实包及隔离 WebView 启动；三端 CI 各自在目标系统构建，产出完整清单后才允许发布。

构建、启动、视觉验收和真实 API 使用分别记录；没有实际证据的项目标记 NOT_RUN。验证不修改真实会话开关、不安装真实插件、不发送付费请求。

## 后续设计：按会话压缩（Proposed，未包含在 0.4.0）

目标是减少长会话后续请求携带的上下文。采用 Claude 原会话的压缩能力，不维护第二份会话摘要，不另起并行执行器，也不改写转录文件。

- 监测使用执行器的 `session.measure` / `session.usage()` 提供的上下文 token、窗口大小和占比；与保活缓存规模、累计 token 分开显示。读数不可得或过期时显示未知，不自动触发。
- 手动操作只作用于选中的、支持该能力的在线空闲会话，通过 `$.command.run({command: 'compact'})` 请求原会话执行。正在工作、续热或压缩时禁用；旧执行器仅提供回原会话执行 `/compact` 的明确提示。
- 条件触发独立于保活开关，每条新连接默认关闭。用户可设置 token 或占比阈值，以及最低空闲时长和冷却时间；窗口大小来自执行器，不按模型名称猜测。开启和保存条件不会影响其他会话。
- 压缩与续热共用互斥调度，压缩优先；执行前再次核对连接身份、读数、条件和空闲状态。压缩后清除旧缓存时钟，等正常请求建立有效缓存后再安排续热。
- 达阈值只触发一次，降到阈值以下后才重新布防；失败或结果未知时停止自动重试。展示压缩前后 token 和结果，不把命令已发出显示为压缩成功。
- 压缩会产生摘要请求和后续新缓存的成本，也可能丢失细节。收益依据实际缩减量和后续请求评估；没有用户的实际 API 单价时只展示 token，不编造节省金额。

参考：[Claude Code 命令](https://code.claude.com/docs/zh-CN/commands)中的 `/compact`，以及 [context-meter 执行链](https://github.com/T-AI-Labs/claude-code-mods/blob/main/context-meter/hooks/register.tsx)的测量事件、原会话命令和阈值重新布防。只借鉴这些机制，不引入其界面或默认全局阈值。实施验收需覆盖手动请求、阈值穿越、工作中跳过、互斥、压缩后缓存失效、错误停止和会话隔离；真实付费压缩不作为自动验收步骤。
